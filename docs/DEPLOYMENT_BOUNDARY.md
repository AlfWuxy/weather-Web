# 生产发布传输与验收边界

部署器的两种模式均在远端写入前校验 SSH 信任与现有公网入口，在原子激活完成后再次做只读验收。独立校验器 `scripts/deployment_boundary.py` 不修改防火墙、服务或证书，不读取 TLS 私钥。

SSH 参数按数组传递，允许端口、身份文件、可信配置、ProxyJump、超时与保活等现有连接设置。严格主机校验固定为 yes，拒绝关闭校验、动态主机信任和空 known_hosts；有效 SSH 配置中的目标必须已经有可信账号持有、不可由其他账号修改的预置主机键。校验不会自动下载或接受主机键。连接复用使用本轮0700临时目录内的独立 socket，不继承先前未知校验状态的连接；自定义 ControlPath 不再用于本次发布。

HTTPS 在发布执行机器外部请求固定站点的 `/healthz`，保留系统 CA 与域名校验，拒绝重定向、非200、非JSON、不带 no-store 或不等于 `{"status":"ok"}` 的响应。使用标明部署用途的浏览器兼容 User-Agent，不绕过403或证书错误。对同域 HTTP `/healthz` 另做不跟随的 HEAD 请求，只接受明确转向同域同路径 HTTPS 的301/302/307/308；HTTP200、跨域跳转或无法证明跳转的403均失败。边缘层终止 HTTPS、源站 Nginx 监听回环8080的既有拓扑可以通过，不要求源站监听443。

源站证据来自已校验 SSH 会话：活动 service 的 MainPID、`/proc` 实际UID、分别成功取得的 IPv4/IPv6 `ss` 监听和接口地址。应用及代理的5000/8080必须只绑定回环，应用主进程必须确实出现在5000监听中且所有应用监听进程属于非root专用账号，同一应用或代理进程不能另开公网监听。从发布机器检查源站每个全局接口地址的5000/8080不得建立TCP连接；网络不可达、地址枚举失败或任一地址族证据未知都会拒绝验收。NAT 等无法枚举公网地址的拓扑需要先补充可核验方案，不能用手写摘要替代。

发布前失败不会进入远端变更。激活后验收失败返回78，明确说明已经激活但未通过安全验收，不调用第二次回滚，也不删除原事务恢复材料；使用原有恢复流程作后续处理。只有激活及安全验收均通过才输出“部署完成”。首次初始化须先建立可核验的边缘入口及服务，不能通过本发布入口跳过安全就绪条件。

本地回归使用真实 `ssh -G` / `ssh-keygen` 解析、临时自签CA的HTTPS服务与合成只读命令证据。通过源码和测试不能替代现场证据；服务器不可连接时不得记录为已部署或已通过线上验收。
