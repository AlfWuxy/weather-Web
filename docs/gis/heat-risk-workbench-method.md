# 都昌县热风险医生工作台：方法、运维与回滚

版本：v2.0（schema 2.0.0）
生成日期：2026-09-26
页面：`/heat-exposure-gis`（默认工作台），`/heat-exposure-gis?ui=legacy`（v1.2 科研版）

## 1. 定位

v1.2 科研版回答“数据是什么”。v2.0 工作台回答“今天先去哪几个村、为什么、去了做什么”，面向乡村医生的日常巡访决策。科研版的七个原始图层、原生几何、SHA-256 指纹和数据表保持不变，仍可随时访问。

## 2. 页面结构

| 区域 | 内容 |
| --- | --- |
| 顶部 | 当日结论一句话、打印今日巡访单、进入科研版 |
| 7 天条 | 逐日热危险等级（0–4），标出“热夜 +1”“热浪 +1” |
| 左栏 | 巡访优先清单（前 5 村，附理由），当日行动卡（医生 / 照护者） |

| 右栏 | 选中格的乡镇与附近村、综合分与等级、排名稳定区间、H/E/V 分项、热点状态、最近医疗点、追溯信息 |
| 下方 | 乡镇汇总表、方法与逐日矩阵、文献与数据、下载 |

## 3. 底图与坐标

图层自下而上为：底图、网格、县界与乡镇界、热点轮廓、注记、选中框、点要素。

| 条件 | 底图 | 叠加要素坐标 |
| --- | --- | --- |
| 配置了 `TIANDITU_TK` | 天地图 `vec_w + cva_w` / `img_w + cia_w` | 保持 WGS84（CGCS2000 与 WGS84 差异远小于 1 m） |
| 未配置 | 高德瓦片 | 前端逐点做 WGS84 → GCJ-02 纠偏后叠加 |
| 瓦片连续失败 | 自动切换为无底图 | WGS84 |

坐标读数始终换算回 WGS84 显示。站内村点（`config.COMMUNITY_COORDS_GCJ`）与后台录入的避暑点按 GCJ-02 处理，服务端先反算为 WGS84 再落格（该区域偏移约 500 m，不纠偏会落错格）。

天地图 key 在 <https://console.tianditu.gov.cn/api/key> 申请，类型选“浏览器端”。浏览器端 key 会出现在页面源码中，属于正常用法，建议在天地图控制台配置域名白名单。

## 4. 综合热风险分

框架：IPCC AR6，风险 = 危险性 × 暴露 × 脆弱性。

- 评分范围：正人口支持且近似永久水域 < 50% 的陆地网格，共 1,606 格。水域 ≥ 50% 的 626 格视为鄱阳湖湖面，不评分。
- H 危险性：2020–2024 夏季 Aqua 白天晴空地表温度均值的平均秩百分位。
- E 暴露：ASPECT 65+ 人口比例的平均秩百分位。
- V 脆弱性：树荫缺口（100 − 树木覆盖）、建成区比例、到最近医疗点距离三项百分位的均值，再取百分位。
- 合成：`Score = 100 × (H × E × V)^(1/3)`，保留一位小数。
- 分级：以 20 / 40 / 60 / 80 为界分为 0 较低、1 轻度、2 中度、3 高、4 极高。当前分布为 193 / 545 / 560 / 291 / 17 格。

分级配色沿用 NWS HeatRisk 的绿、黄、橙、红、品红顺序。

### 4.1 双变量

地表温度与 65+ 比例各取三分位，组合为 3×3 九类（Stevens 配色），c3 表示又热又老。

### 4.2 统计热点

Getis-Ord Gi*，变量为综合分，Queen 8 邻域含自身，二值权重，解析 z 值。多重检验采用 Benjamini–Hochberg FDR：q = 0.05 为显著（虚线），q = 0.01 为强显著（实线）。地图只绘制热点簇外轮廓。

### 4.3 排名稳定性

三项权重各自随机扰动 ±20% 后归一化，固定种子重算 500 次，报告每格“全县前 x%”的第 5 与第 95 百分位（并列分值共享最优名次）。区间跨度 ≤ 20 个百分点视为稳定。

### 4.4 医疗点

OSM 精确点优先（目前只有蔡岭中心卫生院）。其余按“一乡一卫生院”放在 OSM 乡镇驻地点，都昌镇驻地标为县城医疗机构。距离为球面直线距离。村卫生室尚未录入，距离可能偏大。

### 4.5 乡镇

24 个乡镇边界与驻地来自 OpenStreetMap（admin_level=8，ODbL），源文件为 `data/gis/duchang_townships_osm.geojson`。网格按中心点落入多边形归属；落在多边形缝隙（主要是湖岸）的 174 格按最近驻地归属。边界不作为法定行政边界凭证。

## 5. 逐日等级与巡访排序

### 5.1 危险等级

预报来自站内 7 天预报链路（`core.weather.get_forecast_with_cache`，地点 `HEAT_WORKBENCH_LOCATION`，默认“都昌”）。

| 最高气温 | 基础等级 |
| --- | --- |
| < 33 °C | 0 无高温 |
| 33–34.9 °C | 1 偏热关注 |
| ≥ 35 °C | 2 高温（黄色预警量级） |
| ≥ 37 °C | 3 严重高温（橙色预警量级） |
| ≥ 40 °C | 4 极端高温（红色预警量级） |

基础等级 ≥ 1 时，满足下列任一条件则上调一级（最高 4 级）：

- 热夜：最低气温 ≥ 26.5 °C。该阈值为都昌全年日最低气温第 95 百分位，由 `data/raw/逐日数据.csv`（2022-12 至 2025-10，1,036 天）在构建时计算。
- 热浪：连续第 3 个及以上最高气温 ≥ 35 °C 的日子，预报首日会接上已观测的连续高温日数。

### 5.2 逐日矩阵

危险等级为 0 时当日风险为 0。否则按网格静态等级调整：静态 0–1 级 −1，2 级不变，3–4 级 +1，结果限定在 1–4 级。Python（`combine_daily_level`）与 JS（`combineDailyLevel`）使用同一规则，由测试守护。

### 5.3 优先清单

按当日风险、静态综合分、估计老人数（村档案人口 × 老年比例）降序排列，取前 5。行动卡取清单首位村的当日等级。无高温日时地图默认显示静态综合风险。

## 6. 局限

- 65+ 为模型化比例而非人数，暴露分量偏向“老龄化程度”。
- 地表温度不等于 2 米气温；只用了白天晴空观测。
- 全县共用县城单点预报。
- 医疗点多为驻地近似位置，直线距离低估湖区和山区的实际路程。
- 权重为等权，排名尚未用本地就诊结局验证。积累一个夏季的中暑或热相关就诊记录后，应检验综合分与就诊率的相关性，并据此校准权重和阈值。

## 7. 数据构建

```bash
python -m services.heat_risk_workbench_service build
```

默认读取：

- `static/data/gis/duchang_heat_exposure_cells.geojson`
- `data/gis/duchang_townships_osm.geojson`
- `data/raw/逐日数据.csv`

默认输出 `static/data/gis/duchang_heat_risk_workbench.json`。构建结果完全确定（固定随机种子），`tests/test_heat_risk_workbench.py::test_committed_workbench_matches_builder` 会重建并与仓库版本逐字段比对。上游 GeoJSON 更新后（例如加入夜间地表温度或 65+ 人数），重新运行构建并提交输出即可。

## 9. 回滚

按影响从小到大：

1. **单次查看旧版**：访问 `/heat-exposure-gis?ui=legacy`。
2. **全站切回旧版（不改代码）**：在服务器 `.env` 设置 `HEAT_EXPOSURE_GIS_UI=legacy`，重启应用。旧版模板、脚本、样式和 GeoJSON 在本次改造中均未修改。
3. **整页下线**：设置 `FEATURE_HEAT_EXPOSURE_GIS=0` 并重启。
4. **撤销代码**：本次改动以单个 PR squash 合并。在 GitHub 该 PR 页面点击 “Revert”，或在本地执行 `git revert <squash 提交 SHA>` 后走正常 PR 流程。
5. **回到改造前快照**：改造前 main 的提交为 `60ef21f`。如需长期保留标签，可在本地执行：

   ```bash
   git tag -a backup/heat-gis-v1.2-before-workbench 60ef21f -m "热暴露 GIS 工作台改造前"
   git push origin backup/heat-gis-v1.2-before-workbench
   ```
