# 社区探索性空间筛查方法

- 方法版本：`community-exploratory-screening-v1.0.1`
- 模式标识：`exploratory_geospatial_screening`
- 依赖的 GIS schema：`1.2.0`
- 默认冻结证据包 SHA-256：`c72b6d1a9ac9ba2c53bdf3ffdc1aadb14775c15ced2e156674e64be3a8a40237`

## 1. 修复的问题

原社区风险轨要求每个社区同时具备人口、老龄率、慢病率、绿地率、热岛指数、医疗可达性和实测基线门诊量七个字段。现有 `Community` 模型只定义了其中的人口、老龄率和慢病率；绿地率、热岛指数、医疗可达性和实测基线门诊量在加载时为空值。任一字段缺失都会关闭该社区的计算，因此 16 个社区全部显示“数据不足，未参与排名”。

这个现象是完整性门在正常工作。修复采用双轨设计：

1. **完整画像风险轨**：继续使用七字段完整性门。只有经核验的社区画像才能进入天气风险、预计就诊、历史负担、空间热点和行动优先级计算。
2. **探索性空间筛查轨**：使用已冻结、可追溯的公开 GIS 图层生成社区间的相对筛查优先序。它不回填数据库缺失字段，也不解锁临床、就诊或资源调度结论。

探索轨的候选名单来自项目内 `COMMUNITY_COORDS_GCJ` 与 `CITY_LOCATION_MAP` 的规范同名交集。它不要求 `Community` 表先写入 16 行，也不调用实时天气或 DLNM。即使请求中存在实时天气，筛查响应也不计算或暴露温度 RR；正式天气健康风险保持在完整画像风险轨中。

## 2. 字段清单与全榜统一省略规则

| 原完整画像输入 | 当前情况 | 探索性筛查处理 |
| --- | --- | --- |
| `population` | ORM 已有字段，仍需权威分母和时点核验 | 全榜省略 |
| `elderly_ratio` | ORM 已有字段，来源与口径需独立核验 | 全榜省略；筛查轨另用 ASPECT 模型化 `age65_share_pct` |
| `chronic_disease_ratio` | ORM 已有字段，缺少同时点、同空间口径的可公开基线 | 全榜省略 |
| `green_space_ratio` | 当前 ORM 未定义 | 全榜省略；树木覆盖只作为独立环境域，不冒充绿地可达性 |
| `heat_island_index` | 当前 ORM 未定义 | 全榜省略；历史晴空地表温度只作为独立暴露域 |
| `medical_accessibility` | 当前 ORM 未定义 | 全榜省略 |
| `baseline_visits` | 当前 ORM 未定义，也没有通过同社区标识和同时间窗口审核的实测基线 | 全榜省略 |
| 门诊记录与历史负担 | 属于单独的临床数据链，不等同于 `baseline_visits` | 全榜省略 |
| 旧 `vulnerability_index` 与 `risk_level` | 缺少本轮可追溯的字段级生成证据 | 全榜省略 |

“全榜省略”表示该字段对所有社区统一不入分。系统不按社区动态改变字段集和分母，不用中性值、哈希代理值、最近网格或数据库坐标进行静默补齐。进入筛查榜的每个社区始终使用相同的三个评分域和 `1/3` 权重。

## 3. 三个公开 GIS 评分域

| 域与原始字段 | 入分方向 | 时间语义 | 空间语义 |
| --- | --- | --- | --- |
| 年龄敏感性：`age65_share_pct` | 值越高，筛查优先度越高 | ASPECT 2020 年模型化年龄结构 | 100 m 源栅格聚合到原生 MODIS 格；仅正模型人口支持格有值；它不是社区普查老龄率 |
| 地表热暴露：`q3_lst_c_mean` | 值越高，筛查优先度越高 | NASA Aqua MODIS MYD11A1.061，2020-06-01 至 2024-08-31，每年仅 6 至 8 月，Aqua 白天 Q3 质量的晴空地表温度多年均值 | MODIS h28v06 原生正弦投影像元，边长约 926.625 m；它不是当日气温、室内温度或人体体感 |
| 植被缺口：`100 - tree_cover_pct` | 树木覆盖越低，缺口越高，筛查优先度越高 | ESA WorldCover 2020 v100 快照 | 10 m 树木覆盖类按有效源像元覆盖权重聚合到原生 MODIS 格；它不代表公园服务、树荫可达性或个人实际降温暴露 |

`q3_coverage_pct` 必须存在且满足 `0 < q3_coverage_pct <= 100`，页面同时显示 `q3_dates / local_available_dates`。它们用于提醒云遮和质量筛选造成的观测稀疏，不进入得分。当前未对大于 0 的覆盖率设置事后调分阈值。

公开 GIS 包还有 `built_up_pct`、`permanent_water_pct` 和 `mean_elevation_m`。它们暂不入分：建成区与地表温度、树木覆盖存在信息重叠；水体和表面高程对社区脆弱性的方向需要本地方法验证。固定三域可减少看到排名后再选字段的自由度。

## 4. 空间匹配与 1 km 并列

1. 只取 `config.CITY_LOCATION_MAP` 中 16 个命名社区的 WGS84 点坐标。城市 ID、县域默认点和“其他村庄”不进入榜单。
2. 对每个点执行原生 MODIS `Polygon` 的 point-in-polygon。匹配使用 GeoJSON `feature.geometry`，页面的正交近似显示格不用于空间分析。
3. 每个社区必须恰好命中一个原生格。零命中或多格命中都标记具体原因并排除，不使用最近中心格兜底。
4. 当前 16 个命名社区按 point-in-polygon 预计集中在约 8 个唯一原生 MODIS 格。“8”不写入固定结果；每次运行都从当前坐标和当前 GeoJSON 生成匹配社区数与 `unique_cell_count`。

同一原生格内的社区共享相同的三个原始图层值，因此共享筛查得分并并列。分位数参考总体为“合格社区行”；多个社区共享一格时，相同值会按社区单位重复进入分布。输出必须同时报告唯一格数，便于读者识别空间相关性和有效空间信息量。

## 5. 等权分位数公式

设 `E` 为坐标、唯一落格、三个评分域和 Q3 覆盖证据均完整的社区集合。对社区 `c` 与评分域 `k`，采用以最小值为 0、最大值为 100 的平均秩分位。`|E| = 1` 时固定为 50：

```text
P(c,k) = 100 × [count(x(j,k) < x(c,k))
                 + 0.5 × (count(x(j,k) = x(c,k)) - 1)] / (|E| - 1)

tree_gap(c) = 100 - tree_cover_pct(c)

score(c) = [P(c, age65_share_pct)
          + P(c, q3_lst_c_mean)
          + P(c, tree_gap)] / 3
```

分数保持未四舍五入的精度进行降序排名，页面再格式化显示。精确分数相同时使用 dense rank：同分社区获得相同名次和“并列第 N”标签，下一个不同分数的名次加 1。输出同时保留 `rank`、`rank_label`、`tie_count` 和 `is_tied`。

页面另用固定筛查分档帮助阅读：`S1=[0,25)`、`S2=[25,50)`、`S3=[50,75)`、`S4=[75,100]`。`S` 表示 screening score band，不是样本四分位；正式公平性分析中的 Q1-Q4 继续保留独立定义。分档只控制标签和颜色，不改变精确得分或名次。

## 6. 解释上限

该得分只表示“在当前 16 个社区、当前三个公开 GIS 域中的相对空间筛查优先序”。它不支持以下解释：

- 个人或家庭健康风险；
- 当日、实时或预报风险；
- 社区真实患病率、就诊率、超额就诊数或因果效应；
- SIR、Gi* 热点显著性、Impact×Likelihood 或医疗资源建议；
- 16 个社区之外的县域统计推广；
- 对排名相邻社区的实质性差异判断。

每一处页面标题、图例、列表和下载数据都应保留“探索性”与“相对筛查”标识。

方法和来源事实面：

- [后端冻结 GeoJSON 及其 `metadata`](../../data/gis/duchang_heat_exposure_cells.geojson)
- [GIS 发布与回滚说明](./heat-exposure-gis-release.md)

ASPECT 下载数据集的 Figshare 记录 DOI 为 `10.6084/m9.figshare.27323106.v1`；冻结包 `source_versions` 中的 `10.1038/s41597-025-05401-1` 是支持该数据方法的论文 DOI。前者用于定位数据记录，后者用于引用方法论文，两种角色分别保留。

整体输出应保留方法版本、模式、GIS schema、生成时间、研究时段、空间定义、独立复核状态、源版本、输入 SHA-256、匹配/排除计数和唯一格数。每个社区行应保留坐标来源、`cell_id`、三个原始值、Q3 质量证据、域分位、得分、并列状态或排除原因。

筛查链只读取已配置的社区名与 WGS84 点、开放遥感图层和模型化人口聚合值。公开输出不包含姓名、家庭地址、精确住户位置、保险标识、诊断、就诊记录、健康档案或逐户人口。社区点只是空间取样点，不声明为权威边界、法定中心点或住户位置。

## 8. Fail-closed 状态

以下整体异常使筛查模式返回 `unavailable`，不生成排名：

- 文件不是合法 `FeatureCollection`，或缺少必需 `metadata`；
- GIS `schema_version` 不是已审核的 `1.2.0`；
- 项目默认 GeoJSON 的运行时 SHA-256 与已审核指纹不一致；
- `quality_summary.independent_validation != pass` 或 `hard_failures != 0`；
- MYD11A1.061、ASPECT `2020, 100 m` 或 WorldCover `2020 v100, 10 m` 来源声明缺失或不匹配；
- 三个评分域或 Q3 证据的图层 schema 缺失；
- 原生 cell ID、Polygon 几何或必需空间元数据失效；
- 没有任何社区同时通过坐标、唯一落格、三域与 Q3 证据完整性门。

单个社区坐标缺失、落格为零/多个、三域任一值缺失或 Q3 证据缺失时，只排除该社区并返回可审计原因。至少一个社区仍完整时，整体状态为 `partial`。系统不在部分状态下删除评分域或改变权重。

整体证据失败仍返回显式的 `ranking_mode=exploratory_geospatial_screening`、`ranking_status=unavailable` 和具体 `reason_code`。页面不会把证据包损坏、schema 失败或空间匹配失败重新解释为七个临床画像字段缺失。

缓存命名空间为 `community_risk:v5`。缓存键同时绑定排名路径、方法版本、社区画像、规范社区集合、展示坐标和冻结 GeoJSON SHA-256。实时天气缺失的纯筛查与正式天气风险使用不同缓存路径；社区、坐标或证据包变化后会生成新键。

## 9. 版本与未来升级门

方法字段、方向、权重、分位参考总体、并列规则或空间匹配规则变更时，必须更新方法版本并重新回归测试。上游数据刷新时，必须更新 `generated_at_utc`、研究时段、源版本和输入指纹，再从当前数据重算落格数、唯一格数、分位和排名。不兼容的 GIS schema 会停止筛查，等待显式审核。

探索性筛查升级为社区级风险或行动优先级前，至少需通过以下门槛：

1. 用第一方可追溯坐标或权威社区边界替换当前配置点，对点落格与面积加权聚合做敏感性分析。
2. 核验社区人口分母、老龄率和慢病率的来源、时间、单位与覆盖范围。
3. 用诊所/道路旅行时间构建医疗可达性，并获得同社区标识、同时间窗口的实测基线门诊量。
4. 评估约 8 个唯一空间格带来的空间相关性，执行字段选择、权重、时间窗口和落格方法的敏感性检查。
5. 用独立实测或预留样本进行外部验证，预先固定结局、校准、误报/漏报和停止规则。
6. 完成隐私、公平性、误用风险和社区参与审查，并经真人理解度测试确认界面不会把筛查分数误读为临床风险。

全部门槛通过后，才可评审是否把预计就诊、SIR、Gi*、Impact×Likelihood 和资源建议带入产品界面。
