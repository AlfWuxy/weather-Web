# 话术微型试验预注册（v1.0，2026-09-05）

性质：可用性与理解差异研究的预注册；不是效果研究。写在改代码之前。改动本文件需新增版本号并保留旧版。

## 1. 失败事件

2026 年 2 月冬季访谈与 8 月合成用户测试中反复出现同一现象：子女能读懂网页上的预警与行动建议，转述给老人后，老人要么记不住"该做哪一件"，要么把它当成"天气预报"而非"今天要改的事"。系统此前只记录家属是否复制了话术，不知道谁传、怎么传、老人是否复述得出下一步。

## 2. 研究问题

描述性：在都昌家属志愿者可用性测试中，三版短话术在"老人能否说出今天先做哪一步"上是否表现不同？传递者角色与渠道是否与理解正确率相关？

不回答：话术是否提高真实高温日的行动率；是否改善健康。

## 3. 机制假设（每版只改一个机制）

| 版本 | 改动的机制 | 依据（只借方法，不写人名与校名） |
|---|---|---|
| v1_official | 基线：转述官方预警等级与三条建议 | 现有系统默认 |
| v2_gist_why | 要点先行，一句话只讲最重要的一件事，随后用一句解释"为什么" | 老年人风险信息研究：要点（gist）比细节更易保留；说明原因提高遵从 |
| v3_kin_time | 熟人口吻 + 具体时段 + 电费安抚 + 回电承诺 | 风险沟通研究：信使可信度与讯息内容同等重要；电费顾虑是都昌访谈提纲中预设的行动障碍 |

## 4. 话术正文（都昌本地化，普通话书面；方言口播由家属自行转换）

情境：高温（Tmax ≥ 35°C），行动集合 = {中午不下地 / 不出门, 多喝水, 去阴凉或有空调的地方, 不舒服就打电话}

v1_official
```
【高温预警】今天最高 {tmax} 度，{window} 高温。建议：1）中午避免外出和田间劳动；2）多喝水；3）到阴凉或有空调处休息；4）不适及时联系家人。
```

v2_gist_why
```
{elder_call}，今天就记一件事：{window} 别下地、别出门。为什么——今天 {tmax} 度，这个时候太阳最毒，中午出汗多容易头晕摔倒。水放在手边，多喝几口。
```

v3_kin_time
```
{elder_call}，我是{messenger_self}。今天 {tmax} 度，{window} 这段你就在家歇着，别去地里。空调开 28 度就行，一天电费不到一块钱，别省。我 {callback_time} 再给你打电话。
```

情境：寒潮 / 日常两套按同样机制编写（附录 A，随代码提交）。

## 5. 参与者与分母

- 参与者：都昌或九江地区家属志愿者（子女 / 孙辈 / 配偶等），年满 18，自愿，口头同意 + 会话记录。不招募老人本人做效果测试。
- 单位：一次会话 = 一名志愿者 × 一个版本 × 一个情境。
- 目标：每版 ≥ 6 次会话，合计 ≥ 18；不足则如实报告。
- 排除：测试账号自动化脚本产生的事件；同一志愿者同版本重复会话只取第一次。
- 分母：所有完成"复制 → 转述（对着测试人员或录音复述）→ 老人端 teach-back"的会话。

## 6. 指标（全部描述性）

- 理解正确率：teach-back 选项落在当日推荐行动集合内的会话比例（「还没想好」进分母不进分子）。
- 任务时长：从话术页打开到 teach-back 提交的中位秒数。
- 误触率：60 秒内出现矛盾按钮（求助后立刻自报完成）的会话比例。
- 拒绝 / 修改原因：封闭码计数（too_long / unclear_word / wrong_tone / dialect_mismatch / fear_cost / other）。
- 版本修订次数：每版在测试期内被志愿者建议修改并采纳的次数。
- 缺失率：会话未完成 teach-back 的比例。

## 7. 分析

只做交叉表与比例，n<5 单元格遮蔽。不做显著性检验，不做回归。报告写"观察到的差异"，不写"导致"。

## 8. Claim ceiling（申请材料与站内文案的上限）

可写：设计并预注册了一次三版话术的可用性测试；记录了传递者角色、渠道与 teach-back；观察到的理解差异与修改过程。
不可写：某版话术提高老人行动率；家属转述有效；任何健康结果；参与人数以外的覆盖面。

## 9. 伦理与数据最小化

只存角色类别、版本、渠道、封闭码与时间戳。不存姓名、电话、录音、自由文本。志愿者可随时退出并要求删除其会话事件。测试 pair 带 is_test 标记，不进入生产漏斗。

## 10. 时间

W4–W5（2026-09-26 至 10-09）执行；W6 汇总进证据包。真实高温期不再有，本试验不模拟高温环境，只测理解。
